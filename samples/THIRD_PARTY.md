# Sample files: what is in this folder, and where it comes from

The files in `samples/` are **test data**. They are not part of the npm package (`package.json` `files` lists only `dist`, `README.md` and `LICENSE`).

## `.svga` and `.webp` files are never committed

Decision of the repository owner: no `.svga` and no `.webp` file is uploaded to this repository, in any folder (`.gitignore` enforces it, and the git history was cleaned of every such file before the first push). Several of them belong to other people and could not be redistributed under MIT (for example, the YY Inc. animations of github.com/svga/SVGA-Samples are published "for learning use only, commercial use prohibited", and the WebP gallery photographs are reproduced there with the authors' permission only).

Instead, `npm run samples:generate` creates everything the tests need:

* `samples/synthetic/*.webp`: our own animated and still WebP test files (frames drawn by code and encoded by the browser, muxed by `tools/synthetic/webp-muxer.ts`).
* Stand-ins with the names the tests expect: `Rocket.svga` (SVGA 1.x zip + JSON, four bitmap mattes, three matte keys that point at nothing, `movie.spec` as the last zip entry), `angel.svga`, `kingset.svga`, `matteBitmap.svga`, `matteRect.svga`, `Fiery-Red-Dragon.svga` (an MP3 in the images map), `Glossy-Pink-Lips.svga`, `Pink-Heart-Rocket.svga` (170 sprites, 240 frames), `animated.webp` and `static.webp`. They are drawn by code (`tools/synthetic/svga-samples.ts`) and have the same features and names as the files the tests were first written against, but none of the original artwork. They are ours: MIT.
* `samples/expected.json`: what svgaplayerweb (the reference implementation) reads from each `.svga` present.

All of these are git-ignored. A developer can keep real files in `samples/` too: the generator never overwrites an existing stand-in (`--force` does); `npm run samples:expected` then describes whatever is present.
